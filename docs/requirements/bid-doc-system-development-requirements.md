# 云深文档管理系统开发需求文档

## 1. 文档说明

本文档用于指导“云深文档管理系统”的后续产品设计、前端开发、后端开发、联调测试和验收。文档内容基于当前代码仓库状态与需求梳理结果编写，目标是先形成可开发、可验证、可迭代的一期范围。

本文档不等同于最终实施方案。组织架构、审批流程文件等资料仍需由业务方后续提供，开发时应以最终提供文件为准。

配套前端页面与验收细则见：

- [bid-doc-system-frontend-and-acceptance.md](bid-doc-system-frontend-and-acceptance.md)

## 2. 产品定位

系统定位为公司内部使用的投标资料协作与资料库管理系统。

核心目标：

1. 建立公司级和部门级通用资料库，沉淀可复用投标资料。
2. 围绕投标项目建立项目资料区，支持资料收集、引用、审批、版本固化和归档。
3. 支持投标团队协作，跟踪资料清单是否收齐。
4. 通过权限、审批、日志和通知控制资料使用风险。
5. 为普通员工、项目负责人、资料管理员、文件夹管理员、审批人、超级管理员提供不同工作台和操作入口。

一期主线：

- 投标项目协作。
- 通用资料库。
- 项目资料清单。
- 资料上传、引用、版本、有效期。
- 系统内审批流。
- 权限控制、通知、操作日志。
- PC Web 前端。

## 3. 一期用户和角色

### 3.1 普通员工

普通员工是系统基础使用者。

主要职责：

- 查看自己有权限的项目和资料。
- 上传自己负责的资料。
- 补全资料元数据。
- 查看、预览、下载自己有权限的资料。
- 接收资料待补充、审批结果、资料过期等系统内通知。
- 对自己负责的资料进行更新。

限制：

- 不能查看无权限资料。
- 不能管理项目。
- 不能管理文件夹授权。
- 不能维护系统配置。
- 对敏感或机密资料的预览、下载、使用可能需要审批。

### 3.2 项目负责人

项目负责人和项目管理员合并为同一个概念。一个项目至少有一个项目负责人，可设置多个项目负责人。

主要职责：

- 创建和维护投标项目。
- 管理项目成员。
- 维护项目资料清单。
- 指定清单项责任人。
- 跟踪项目资料收集进度。
- 引用通用资料库资料。
- 发起项目相关审批。
- 推进项目阶段。
- 归档项目。
- 查看自己负责项目范围内的操作日志。

### 3.3 资料负责人

资料负责人是可选项目角色。

主要职责：

- 协助项目负责人跟踪资料清单。
- 负责资料收集进度。
- 处理资料补充提醒。
- 协调项目成员补齐资料。

说明：

- 小项目可以不设置资料负责人。
- 大项目可以设置一个或多个资料负责人。
- 资料负责人不自动拥有项目全部管理权限，具体权限由项目角色配置决定。

### 3.4 资料管理员

资料管理员管理资料本身，管理范围由超级管理员配置。

可配置范围：

- 全局资料。
- 指定部门或事业部资料。
- 指定资料类型。
- 指定文件夹或资料区。

主要职责：

- 维护资料元数据。
- 管理资料分类、敏感等级、有效期。
- 管理资料版本。
- 处理资料作废、恢复等操作。
- 跟踪即将过期或已过期资料。
- 发起资料相关审批。
- 查看自己管理范围内的资料日志。

### 3.5 文件夹管理员

文件夹管理员管理存放空间和协作范围。

主要职责：

- 管理被授权文件夹及子文件夹。
- 创建、重命名、移动、删除文件夹。
- 配置文件夹授权。
- 设置文件夹协作者或管理员。
- 管理文件夹范围内资料的组织方式。

资料管理员和文件夹管理员权限点分开，但人员可以重叠。同一个人可以同时拥有资料管理员和文件夹管理员身份。

### 3.6 审批人

审批人根据审批流程节点配置获得审批待办。

主要职责：

- 处理当前节点审批。
- 通过或驳回审批。
- 按权限加签或移交。
- 查看自己参与的审批历史。

限制：

- 非当前节点处理人不能审批。
- 加签、移交需要满足部门、角色、数据范围和流程权限要求。

### 3.7 超级管理员

超级管理员是系统最高权限角色。系统不再单独设置“系统管理员”角色，也不设置“流程管理员”角色。

主要职责：

- 管理用户、部门、角色基础配置。
- 维护资料分类、投标结构分类、敏感等级、项目类型、项目阶段。
- 维护资料清单模板。
- 维护审批流程和流程匹配规则。
- 处理审批异常。
- 配置资料管理员和文件夹管理员范围。
- 查看全局日志和统计。
- 执行特殊操作，例如物理删除、归档例外更新。

规则：

- 超级管理员不受业务审批限制。
- 超级管理员所有操作必须记录日志。

## 4. 组织架构

### 4.1 组织模型

系统只面向当前公司内部使用，不做多公司、多租户或商业 SaaS。

组织结构为单公司树形组织架构：

- 公司。
- 事业部。
- 部门。
- 科室。
- 其他组织节点。

事业部就是组织部门树中的部门节点，例如干变事业部、箱变事业部、开关事业部等。事业部下可以有科室、营销部、技术室等子部门。有些部门下没有科室。

系统必须严格按业务方后续提供的组织架构文件初始化部门树。

待提供资料：

- 正式组织架构文件。
- 部门编码。
- 事业部缩写。
- 用户与部门关系。

### 4.2 部门权限继承

一期按角色决定是否向下继承部门权限。

规则：

- 普通部门成员不因为所在部门自动拥有部门内全部资料权限。
- 部门负责人或事业部管理员默认可管理本部门及下级部门范围内数据。
- 项目负责人管理自己负责项目内的数据。
- 文件夹管理员管理被授权文件夹及其子级范围。
- 资料管理员按超级管理员配置的数据范围管理资料。
- 超级管理员拥有全局权限。

二期可考虑将“是否包含下级部门”做成可配置权限范围。

## 5. 投标项目

### 5.1 项目范围

一期采用标准项目能力，不做完整投标流程管理。

项目基础信息包括：

- 项目编号。
- 项目名称。
- 招标单位。
- 投标截止时间。
- 所属事业部或部门。
- 项目类型。
- 项目阶段。
- 项目状态。
- 项目负责人。
- 项目成员。
- 资料负责人，可选。
- 项目资料清单。
- 项目资料区。

后续可扩展完整投标流程，包括报名、资格预审、保证金、开标、中标结果、归档复盘等。

### 5.2 项目编号

项目编号由系统自动生成。

暂定格式：

```text
事业部缩写-YYYYMMDD-流水号
```

示例：

```text
GB-20260612-001
XB-20260612-001
KG-20260612-001
```

生成规则：

- 创建项目时，根据项目所属事业部生成编号。
- 事业部缩写由超级管理员在部门配置中维护。
- 同一事业部、同一天内流水号递增。
- 流水号默认三位，不足三位补零。
- 项目编号生成后不再变化。
- 如果项目后续调整所属事业部，历史项目编号不变。
- 如果事业部未配置缩写，不允许创建项目，并提示先维护事业部缩写。

### 5.3 项目阶段

项目阶段可配置，默认阶段为：

- 资料收集中。
- 资料审核中。
- 投标文件编制中。
- 待提交。
- 已提交。
- 已归档。
- 已取消。

规则：

- 超级管理员可以调整阶段名称、顺序和启停状态。
- 项目负责人可以推进项目阶段。
- 阶段变更必须记录日志。
- 阶段变更可触发系统内通知。

### 5.4 项目状态

项目阶段表达业务进度，项目状态表达系统控制状态。

默认状态：

- 正常。
- 暂停。
- 归档。
- 取消。
- 删除。

规则：

- 前端业务页面主要展示项目阶段。
- 后端权限、可编辑性、是否可审批、是否可归档主要依据项目状态控制。
- 已归档项目整体只读。
- 已取消项目停止资料收集和审批任务，但保留历史记录。
- 已删除项目默认不可见，保留日志。

## 6. 通用资料库

### 6.1 资料库结构

通用资料库采用“部门 + 资料类型”结合的结构。

默认分区：

- 公司公共资料区。
- 各事业部或部门资料区。
- 项目沉淀资料区。

部门资料区下按资料类型组织，例如：

- 企业资质。
- 人员证书。
- 项目业绩。
- 财务资料。
- 法务资料。
- 技术方案。
- 商务文件。
- 报价资料。
- 模板文件。
- 其他。

规则：

- 文件夹允许管理员调整。
- 默认结构可由系统初始化或模板生成。
- 文件夹权限和资料权限同时生效。
- 项目引用通用资料时，只能从用户有权限的资料区选择。

### 6.2 资料分类

系统同时支持两类分类：

1. 资料业务分类。
2. 投标文件结构分类。

资料业务分类用于资料库长期管理，例如：

- 企业资质。
- 人员证书。
- 项目业绩。
- 财务资料。
- 法务资料。
- 技术方案。
- 商务文件。
- 报价资料。
- 模板文件。
- 其他。

投标文件结构分类用于具体项目投标材料组织，例如：

- 资格审查资料。
- 商务标资料。
- 技术标资料。
- 报价资料。
- 合同资料。
- 归档资料。

同一份资料在资料库中有业务分类，在不同项目中可以被放入不同投标结构分类。

### 6.3 资料编号

每份正式资料生成唯一资料编号。

规则：

- 资料编号由系统生成。
- 编号用于搜索、引用、审批、日志、归档和版本追踪。
- 编号和文件名分离。
- 文件名可以修改，资料编号不变。
- 同一资料的新版本沿用同一个资料编号。
- 不同版本通过版本号区分。
- 临时过程文件是否生成编号，由是否转为正式资料决定。

后续可扩展：

- 按资料类型配置编号规则。
- 按事业部或部门配置编号前缀。
- 按年份、项目类型等生成编码。

## 7. 资料模型

### 7.1 原始归属和使用范围

资料采用“原始归属 + 使用范围”模型。

原始归属可以是：

- 个人。
- 项目。
- 部门。
- 公司级。

使用范围可以是：

- 项目。
- 部门。
- 文件夹。
- 指定角色或数据范围。

规则：

- 原始归属决定资料来源和基础权限。
- 使用范围决定协作和复用权限。
- 实际能否查看、预览、下载、更新，由角色权限、使用范围、敏感等级、资料状态共同决定。

### 7.2 敏感等级

敏感等级可配置。

系统初始化默认提供四级：

- 公开。
- 内部。
- 敏感。
- 机密。

超级管理员可配置：

- 等级名称。
- 等级说明。
- 排序。
- 是否启用。
- 默认审批策略。

规则：

- 普通用户上传或维护资料时，从已启用等级中选择。
- 权限和审批判断基于等级配置。
- 管理员上传、更新、替换敏感资料时默认可直接通过。
- 管理员也可以主动提交审批。
- 超级管理员不受业务审批限制。

### 7.3 必填元数据

正式资料必填项按资料类型配置，默认必填项为：

- 资料名称。
- 资料分类。
- 敏感等级。
- 归属部门或事业部。
- 资料来源。
- 有效期类型。
- 是否有有效期。

按资料类型可扩展：

- 人员证书：绑定人员、证书类型、证书编号、有效期。
- 项目业绩：绑定业绩项目、合同金额、项目类型、年份。
- 财务资料：绑定年度、报表类型。
- 法务资料：合同、授权、证明类型。
- 技术方案：适用产品线、适用项目类型。
- 模板文件：模板类型、适用阶段。

规则：

- 文件上传成功后可以处于待补全状态。
- 元数据补齐后才能提交审批或进入正式资料库。
- 未配置资料类型必填项时使用默认必填项。

### 7.4 有效期

不是所有资料都有有效期。系统需要兼容有有效期和无有效期资料。

规则：

- 有有效期的资料记录生效日期和失效日期。
- 无有效期资料不参与过期判断。
- 项目引用资料时，已过期资料不能算清单已收齐。
- 即将过期资料需要风险提示。
- 普通用户收到过期提醒后主要负责更新资料。
- 项目负责人和资料管理员负责判断项目资料是否满足要求。
- 不做 OCR 或 AI 自动识别有效期。

过期资料使用规则：

- 按资料类型配置是否允许继续使用。
- 有些资料类型过期后绝对不能使用。
- 有些资料类型允许走例外使用审批。
- 项目负责人和资料管理员都可以发起过期资料例外使用审批。
- 审批通过后，仅对指定项目、指定资料、指定版本生效。

### 7.5 文件版本

一期版本规则：

- 重新上传或替换文件内容时生成新版本。
- 修改文件名、标签、分类、敏感等级、有效期、说明等元数据不生成文件版本。
- 元数据变更必须记录操作日志。

每个版本记录：

- 版本号。
- 文件大小。
- MIME 类型。
- 存储对象 key。
- 上传人。
- 上传时间。
- 变更说明。
- 审批状态。

项目引用资料时引用具体版本号。归档项目锁定当时引用版本。

## 8. 项目资料清单和模板

### 8.1 资料清单模板

资料清单模板以项目类型管理。

规则：

- 模板按项目类型区分。
- 模板包含多个资料清单项。
- 模板可以复制。
- 模板可以调整。
- 模板可以启用或停用。
- 停用后新项目不可选择，历史项目不受影响。
- 修改模板不影响已经创建的历史项目，除非项目负责人手动同步。

### 8.2 项目资料清单

项目创建时可选择模板生成项目自己的资料清单副本。

清单项字段包括：

- 清单项名称。
- 说明或要求描述。
- 是否必需。
- 资料业务分类。
- 投标文件结构分类。
- 建议敏感等级。
- 默认审批要求。
- 允许资料来源：通用资料库、项目上传、两者均可。
- 允许文件类型。
- 数量要求。
- 截止时间。
- 责任人。
- 状态。

清单项状态：

- 待收集。
- 待审核。
- 需补充。
- 已收齐。
- 已替换。
- 已归档。

规则：

- 资料未上传时，清单项为待收集。
- 资料已上传但未审批通过时，清单项不能是已收齐。
- 资料审批通过且满足要求后，清单项才可为已收齐。
- 资料被驳回时，清单项变为需补充。
- 资料被新版本替换时，原资料进入已替换，新资料重新判断状态。
- 项目归档后，清单项随项目归档冻结。

### 8.3 项目资料区

项目资料区采用“清单驱动 + 文件夹辅助”。

规则：

- 项目资料清单是主线。
- 项目成员围绕清单项上传资料或引用通用资料。
- 每个清单项可以绑定一份或多份资料。
- 清单项满足条件后才显示已收齐。
- 项目负责人可以创建辅助文件夹。
- 辅助文件夹用于过程文件、临时资料、沟通材料。
- 辅助文件夹资料如果不绑定清单项，不计入资料收齐状态。

## 9. 资料引用和同步

### 9.1 引用和固化版本

项目使用通用资料时采用“引用 + 固化版本”。

规则：

- 项目引用通用资料时，默认锁定某个资料版本。
- 通用资料库后续更新，不自动影响项目已引用资料。
- 项目归档后固定当时引用版本。
- 历史投标项目不因资料库更新而变化。

### 9.2 手动同步版本

如果通用资料有新版本，项目负责人或资料管理员可以主动同步。

规则：

- 页面提示“有新版本可用”。
- 管理员可选择同步到最新版本。
- 管理员可选择指定版本。
- 同步动作记录日志。
- 同步敏感资料或关键资料时可触发审批。
- 已归档项目默认不允许普通同步。
- 归档项目需要更新资料版本时，作为例外操作处理。

## 10. 上传、预览、下载、删除

### 10.1 上传限制

一期上传限制采用基础限制。

限制项：

- 文件大小。
- 文件类型。
- 单次上传数量。

规则：

- 上传失败要有明确错误提示。
- 上传进度要可见。
- 上传成功后再补充资料分类、敏感等级、有效期、标签等元数据。
- 上传阶段不直接代表资料可正式使用。
- 资料是否生效、能否被项目引用、是否算收齐，由审批、资料状态和清单绑定规则决定。

### 10.2 预览和下载

预览和下载是两个不同权限点。

规则：

- 能预览不代表能下载。
- 敏感等级可以影响下载策略。
- 公开和内部资料通常可按权限下载。
- 敏感和机密资料可能只允许预览，或下载需要审批。
- 超级管理员不受限制，但预览和下载必须记录日志。
- 一期不做水印、防截屏、防复制、防外发。

### 10.3 删除

一期删除采用逻辑删除和回收站。

规则：

- 默认逻辑删除。
- 删除后普通列表不可见。
- 删除操作必须记录日志。
- 项目归档资料不允许普通删除。
- 删除被项目引用的资料时，需要提示影响范围。
- 回收站用于查看和恢复已删除资料。
- 管理员可按权限恢复。
- 物理删除只允许超级管理员在特定条件下执行。
- 物理删除必须二次确认并记录日志。
- 已参与审批、归档、项目引用的资料，原则上不允许物理删除，只能作废或隐藏。

## 11. 项目归档

项目结束后进入归档状态。

归档规则：

- 归档项目整体只读。
- 不允许随意修改项目结构、清单、审批结果。
- 归档时记录当时使用的资料版本。
- 归档时记录审批记录、清单状态、操作日志。
- 归档后资料本身仍允许在通用资料库继续更新。
- 归档项目引用的是当时版本，不会被资料后续更新自动改变。
- 如果确实需要更新归档项目中的资料版本，走特殊权限或特殊流程。

## 12. 审批流

### 12.1 审批定位

审批在本系统内实现，不对接外部 OA、企业微信、钉钉或其他审批系统。

审批流程文件由业务方后续提供。文档和开发应以最终审批流程文件为准。

审批是核心子系统，不是简单的固定审批人机制。

### 12.2 审批触发

一期触发范围：

- 新增上传资料。
- 更新资料版本。
- 使用敏感资料。
- 跨项目或跨部门引用受限资料。
- 过期资料例外使用。
- 管理员主动提交审批。

二期预留：

- 规则引擎式审批。
- 根据资料分类、敏感等级、归属范围、操作类型、操作者角色等组合判断。

### 12.3 流程匹配

一期流程匹配按：

- 事业部或部门。
- 资料类型。
- 操作类型。

规则：

- 项目归属某个事业部或部门。
- 资料类型决定审批流程分类。
- 操作类型决定流程场景，例如上传、更新、敏感资料使用、过期例外使用。
- 如果匹配不到专用流程，走该事业部或部门默认流程。

二期可扩展：

- 项目类型。
- 敏感等级。
- 金额。
- 截止时间。
- 其他条件。

### 12.4 审批能力

一期审批流需支持：

- 流程定义。
- 节点定义。
- 条件判断。
- 条件分支。
- 审批权限控制。
- 审批通过。
- 审批驳回。
- 发起人撤回。
- 加签。
- 移交。
- 审批历史。
- 审批状态回写。
- 审批通知。
- 审批日志。

### 12.5 驳回和撤回

规则：

- 审批人驳回时可以选择驳回到发起人，修改后从头审批。
- 审批人也可以选择驳回到指定节点，修改后从指定节点继续。
- 资料被驳回后状态为已驳回。
- 对应项目清单项变为需补充。
- 发起人可修改资料或补充说明后重新提交。
- 审批完成前，发起人可以撤回。
- 撤回后资料回到待提交或待补充状态。
- 驳回、撤回、重新提交都要通知相关人并记录日志。

### 12.6 加签和移交

规则：

- 支持审批中加签。
- 支持当前审批人移交待办。
- 加签和移交必须填写原因。
- 加签和移交进入审批历史。
- 加签和移交进入操作日志。
- 只有当前审批人和超级管理员可以加签或移交。
- 可加签或移交人员受部门、角色、流程权限控制。

### 12.7 审批权限控制

审批权限采用角色、流程节点配置、数据范围组合判断。

发起权限：

- 根据用户角色判断能否发起某类审批。
- 根据业务对象判断是否有权操作该资料、项目、文件夹。

处理权限：

- 根据流程节点配置判断谁可以处理。
- 节点可配置角色、部门、岗位或指定人员规则。
- 用户还必须满足数据范围要求。

数据范围：

- 项目范围。
- 部门或事业部范围。
- 文件夹管理范围。
- 资料管理范围。

## 13. 权限控制

### 13.1 权限对象

权限矩阵覆盖：

- 资料。
- 文件夹。
- 项目。
- 审批。
- 通知。
- 日志。
- 系统配置。

资料权限点：

- 查看。
- 预览。
- 下载。
- 上传。
- 补全元数据。
- 提交审批。
- 审批。
- 更新版本。
- 同步版本。
- 删除。
- 恢复。
- 作废。

文件夹权限点：

- 创建。
- 查看。
- 重命名。
- 移动。
- 删除。
- 授权。
- 设置管理员。

项目权限点：

- 创建。
- 查看。
- 编辑。
- 成员管理。
- 清单管理。
- 资料绑定。
- 阶段推进。
- 归档。
- 取消。

系统配置权限点：

- 用户。
- 部门。
- 角色。
- 敏感等级。
- 资料分类。
- 模板。
- 项目阶段。
- 审批流程。

### 13.2 权限冲突原则

当用户同时拥有多个角色或局部身份时：

- 多角色权限默认取并集。
- 如果存在明确禁止规则，则禁止优先。
- 敏感和机密资料可设置更严格限制。
- 审批要求不等同于禁止，要求审批时必须审批通过后才能执行。
- 超级管理员不受业务权限限制。
- 超级管理员所有操作必须留痕。
- 权限判断结果需要可解释，例如无下载权限、资料需审批、资料已过期不可使用。

### 13.3 外部协作人

一期不支持外部协作人。

规则：

- 只支持公司内部员工账号登录使用。
- 不提供外部账号。
- 不提供临时上传链接。
- 不允许供应商、合作单位、专家直接访问系统。
- 外部资料由内部员工代为上传。

## 14. 通知

通知只做系统内通知。后期也不规划短信、邮件、企业微信、钉钉、公众号等外部通知。

一期通知范围：

- 资料待上传。
- 资料被驳回。
- 审批待办。
- 审批结果。
- 资料即将过期。
- 资料已过期。
- 项目创建。
- 被加入项目。
- 项目截止提醒。
- 清单项逾期。
- 项目归档。
- 文件夹或资料被授权。
- 权限被变更。
- 敏感资料使用申请结果。

所有关键操作都必须留痕，包括：

- 登录。
- 退出。
- 上传。
- 预览。
- 下载。

- 恢复。

- 修改元数据。
- 授权。
- 权限变更。

- 审批通过。
- 审批驳回。
- 审批撤回。
- 加签。
- 移交。
- 项目归档。

日志可见范围：

- 项目负责人查看自己负责项目范围内日志。
- 部门或事业部负责人查看本部门及下级部门范围内日志。
- 资料管理员查看自己管理资料范围内日志。
- 审批人查看自己参与审批流程相关日志。
- 超级管理员查看全局日志。

二期可支持更细审计权限配置。

## 18. 文件存储

一期采用 MinIO 对象存储。

规则：

- 开发、测试环境也对接 MinIO。
- 可通过 Docker 部署开发测试 MinIO。
- 本地存储只作为开发兜底，不作为主要验收路径。
- 生产环境 MinIO 部署拓扑暂不锁定，后续单独评估。
- 数据库存储对象 key、bucket、文件名、大小、MIME、版本号等元数据。
- 不对前端暴露真实存储路径。

## 19. 前端和客户端范围

一期只做 PC Web。

规则：

- 不做移动端。
- 不做小程序。
- 不做 App。
- 不要求手机浏览器适配。
- 支持 Chrome 最新稳定版。
- 支持 Edge 最新稳定版。
- 不支持 IE。
- 不专门适配国产浏览器兼容模式。

工作台规则：

- 项目负责人默认进入项目管理工作台。

- 超级管理员默认进入管理数据看板。

## 20. 数据初始化

规则：

## 23. 验收方式

验收方式采用功能级验收为主，关键流程补测试用例级验收。

验收原则：

- 每个核心模块有明确可验证行为。
- 权限相关需求必须验证正向和反向场景。
- 审批相关需求必须验证通过、驳回、撤回、加签、移交。
- 日志相关需求必须验证操作后有记录。
- 通知相关需求必须验证触发人和接收人。
- 项目归档、版本固化、资料同步必须验证历史版本不被自动改变。
